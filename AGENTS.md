# AGENTS.md — operating manual for coding agents

This file is the source of truth for any AI agent (or human) working on
Nutshell. Read it fully before making changes. It defines the roles, the
rules, the build/verify commands, and the exact milestone-by-milestone path
from "boots to a banner" to "boots into a working shell."

If anything here conflicts with a code comment or a stray note elsewhere,
**this file wins.**

---

## 1. Roles

Nutshell is built with a two-role workflow:

- **Orchestrator** — plans the work, defines each milestone and its Definition
  of Done, reviews diffs, and keeps the docs and roadmap honest. The
  orchestrator does *not* dump large implementations; it decides *what* and
  *in what order*, and checks the result.
- **Builder** — the agent that implements one milestone at a time against the
  spec in `docs/milestones/`, keeping the build green at every step.

If you are the Builder, your loop is: **pick the lowest-numbered unfinished
milestone → implement it → make the build and boot pass → tick its Definition
of Done → update the roadmap and CHANGELOG → stop for review.** Do exactly one
milestone per pass. Do not jump ahead.

## 2. Ground rules (non-negotiable)

1. **The build must never break.** Every commit must `make` cleanly and
   `make run` must still boot in QEMU. If a milestone is large, land it in
   smaller commits that each keep the build green.
2. **Freestanding only.** No host libc, no standard library, no external
   dependencies. The only headers allowed are the freestanding ones the
   compiler itself provides: `<stdint.h>`, `<stddef.h>`, `<stdbool.h>`.
   If you need `memcpy`/`memset`/`strlen`, write them (put them in
   `src/string.c`).
3. **Warnings are errors in spirit.** Code must compile clean under
   `-Wall -Wextra`. Don't silence warnings — fix the cause.
4. **Every new `.c` file drops into `src/` and every header into `include/`.**
   The Makefile auto-discovers them via a wildcard; no Makefile edits needed
   for new modules.
5. **No feature without a doc.** If a milestone introduces a subsystem
   (interrupts, memory, keyboard, shell), its concept doc in `docs/` must be
   accurate when the milestone lands.
6. **Small, honest commits.** See the commit style below.
7. **When unsure, prefer the OSDev-wiki-canonical approach** over a clever
   shortcut. This project's value is clarity and correctness, not novelty in
   the bring-up code.

## 3. Build, run, verify

All commands run from the repo root on Ubuntu / WSL2.

| Command | What it does |
|---------|--------------|
| `./scripts/setup-wsl.sh` | Install the toolchain (one time). |
| `make` | Compile and link `build/kernel.bin`. |
| `make iso` | Build the bootable ISO `build/nutshell.iso`. |
| `make run` | Build the ISO and boot it in QEMU (serial → terminal). |
| `make debug` | Boot halted with a GDB stub on `:1234`. |
| `make clean` | Remove `build/`. |

**Definition of "it works" for any change:**
1. `make clean && make iso` succeeds with no warnings.
2. `make run` boots to the expected screen output.
3. For headless verification, the serial log contains the expected markers
   (this is exactly what CI checks — see `.github/workflows/ci.yml`).

Never claim a milestone is done without having actually booted it.

## 4. Coding standards

- **C**: C11, 4-space indent, K&R-style braces, `snake_case` for functions and
  variables, `UPPER_CASE` for macros and constants. Keep functions short and
  single-purpose. Comment *why*, not *what*.
- **Assembly**: NASM syntax, lower-case mnemonics, a comment block at the top
  of each file explaining what state it assumes on entry and guarantees on
  exit.
- **Headers**: `#pragma once`, declarations only, no logic.
- **No magic numbers** in C where a named constant reads better (port numbers,
  bit flags, IRQ lines). Assembly bring-up code may use documented literals.
- **Ports/IO**: put `inb`/`outb` and friends in `include/io.h` once more than
  one file needs them (milestone 3).

## 5. Commit and branch style

- Format: `type(scope): outcome`, imperative mood, lower case.
  Examples: `feat(idt): install 64-bit interrupt descriptor table`,
  `fix(vga): correct scroll on last row`, `docs(roadmap): mark milestone 2 done`.
- Types: `feat`, `fix`, `docs`, `refactor`, `build`, `chore`, `test`.
- Body only if it adds real information. Keep it minimal.
- **Do not add AI/co-author trailers or "generated by" lines.** Commits are
  authored by the repo owner.
- Work on a branch per milestone (`milestone-3-interrupts`), open a PR into
  `main`, keep CI green.

## 6. The milestone path (what "finished" means)

Each milestone has a full spec with tasks and a Definition of Done in
`docs/milestones/`. Summary of the whole road:

| # | Milestone | Adds | Spec |
|---|-----------|------|------|
| 0 | Boot | multiboot2, 32→64-bit, paging, VGA + serial banner | [spec](docs/milestones/milestone-0-boot.md) ✅ |
| 1 | I/O | `kprintf`, formatted VGA + serial output | [spec](docs/milestones/milestone-1-io.md) |
| 2 | GDT | proper 64-bit GDT (+ TSS stub) in C | [spec](docs/milestones/milestone-2-gdt.md) |
| 3 | Interrupts | IDT, remap 8259 PIC, exceptions, IRQs, PIT | [spec](docs/milestones/milestone-3-interrupts.md) |
| 4 | Keyboard | PS/2 IRQ1, scancode decode, input ring buffer | [spec](docs/milestones/milestone-4-keyboard.md) |
| 5 | Memory | physical frame allocator + kernel heap (`kmalloc`) | [spec](docs/milestones/milestone-5-memory.md) |
| 6 | Shell | REPL + built-ins (`help`, `echo`, `clear`, `mem`, `uptime`, `reboot`) | [spec](docs/milestones/milestone-6-shell.md) |
| 7 | Polish | tests, CI, README GIF, tag `v1.0.0` | [spec](docs/milestones/milestone-7-polish.md) |

**Definition of Done for the whole project (Milestone 6 reached, 7 polished):**
Nutshell boots in QEMU into an interactive prompt where the user can type
commands and get responses, all running on the bare kernel with no host OS.

## 7. What NOT to do

- Do not add a third language, a package manager, or any dependency.
- Do not pull in an existing bootloader/kernel's code; write it here.
- Do not skip the boot/serial verification because "it should work."
- Do not refactor unrelated code inside a milestone PR.
- Do not enable SSE/MMX/floating point in the kernel build (the flags in the
  Makefile disable them on purpose; the kernel has no FPU state handling yet).

## 8. Tools reference

- **NASM** — assembler for `boot/*.asm`.
- **gcc + binutils (ld)** — freestanding C compiler and linker. A
  `x86_64-elf-*` cross-toolchain is the "proper" upgrade; override `CC`/`LD`
  on the make command line to use it.
- **GRUB (`grub-mkrescue`) + xorriso + mtools** — build the bootable ISO.
- **QEMU (`qemu-system-x86_64`)** — the machine we boot on.
- **GDB** — source-level debugging via `make debug` (see docs/09).

That's the whole contract. Build one milestone, boot it, prove it, document
it, commit it. Then the next.
